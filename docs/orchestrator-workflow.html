Overview

Four cooperating skills. Scripts do everything deterministic; the LLM interviews, judges escalations and talks to the user.

script / supervisor (deterministic)agent / LLM judgmentuser decision / gatesuccessblocked / failuregit / journal

1 · Pre-flight: nothing is built or run without asking

check names the first missing input. When a step is missing entirely the agent must ask the user first and record the answer (consent); each skill still ends with the user’s explicit approval, written to the committed ledger.

2 · Is there a previous run?

Always assess before run. One run is active per project (lock); run refuses crashed, inconsistent or drifted runs until a decision is confirmed.

3 · Run and supervise

The supervisor runs detached and pushes its own digests (default every 5 min) and alerts. The agent loops on wait and reacts only to events that need judgment.

4 · What the supervisor does for every task

Parallel tasks each run this pipeline in their own worktree. Evidence is produced by the supervisor, not claimed by agents; the PASS verdict is computed by code.

5 · State machines

Generated from TASK_TRANSITIONS and MILESTONE_TRANSITIONS; illegal transitions throw.

Task

  1. PLANNED → READY all dependencies INTEGRATED and milestone ACTIVE
  2. READY → RUNNING dispatched to an implementer (capacity + scope free)
  3. RUNNING → REVIEW committed; scope check and verify commands green
  4. RUNNING → REWORK evidence failed (verify / scope / agent run) — findings attached
  5. RUNNING → READY supervisor restart / stop: interrupted work resumes (worktree kept)
  6. REVIEW → PASS independent review verdict computed PASS
  7. REVIEW → REWORK review FAIL or any non-PASS criterion
  8. REWORK → RUNNING re-dispatched in the same worktree
  9. PASS → INTEGRATED merged --no-ff + regression verify ok
  10. BLOCKED → READY operator unblock (extra rounds / other agent)
  11. any active state → BLOCKED retries exhausted, merge conflict, regression, spawn error, unverifiable review (dashed red)

Milestone

  1. PLANNED → ACTIVE dependency milestones DONE; branch + integration worktree ready
  2. ACTIVE → GATE every task INTEGRATED
  3. GATE → AWAITING_APPROVAL milestone verify commands passed
  4. GATE → DONE when approvals.milestone_merge is false
  5. GATE → ACTIVE gate interrupted by stop
  6. AWAITING_APPROVAL → DONE approved (confirmed) → merge policy applied
  7. BLOCKED → ACTIVE operator unblock → tasks continue
  8. BLOCKED → GATE operator unblock → re-run gate
  9. any active state → BLOCKED retries exhausted, merge conflict, regression, spawn error, unverifiable review (dashed red)

Rework is bounded

max_rework_rounds (+ operator extras), then BLOCKED. A task cannot be marked passed by anyone but the verdict.

Gates

  • plan approved before any run
  • milestone gate verify, then user approval
  • merge policy: manual (branch left for you) or local

6 · Crash, resume and reset

The event log is write-ahead truth; state is rebuilt from it. Nothing is deleted without a separate, confirmed prune.

7 · Audit trail and replay

Everything an external supervisor or reviewer needs to understand, replay or resume a run.
